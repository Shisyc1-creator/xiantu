# 第四十批 · 账目与帮助版

日期：2026-10-22。基于第三十九批宣纸墨朱砂界面版，完成 M0 与 D0 基础。

## 本批变化

- 灵石按整枚持有、展示与支付。营生、行走收入和灵田看护按实际经过的天数累计；不足一枚的部分作为不能提前花费的应计权益保留，足额后到账。
- 年收入、闭关费用先生成整数报价，再按周期结算。当前物价倍率机制仍沿用旧规则；地方供需与长期平衡属于后续阶段。
- 玩家事件、交易、制作、置业、月俸、宗门费用、药路报酬、百草铺赠资/垫款/还款与继承均接入统一收支入口。保存最近120笔整数变动的日期、来源、金额与余额，帮助的货币分类可查看最近20笔。
- 个人灵石仍按四成传承，该份额内不足一枚的权益也保留；店铺债权沿用既有记名接续规则，不复制为新收入。
- 人物页“卷宗”改为“设置”。人物 → 设置 → 玩法说明，以及界面设置里的“帮助”，均进入统一帮助页。八个分类支持跨分类关键词搜索，场景、商铺、家园、制作等页面问号直接定位相关说明。
- 通用的功法、委派说明收入帮助，页面保留当前条件、费用、库存、月俸、期限和失败代价。

## 旧档与模式基础

首次读取不含新账本的旧档，先向浏览器本地存储保存原始 JSON，确认写入成功才载入。整数余额进入可用灵石，十进制零头按原数值精确保留；不向上赠送一枚。重复加载相同旧档不重复备份，迁移后的存档不会再次转换。

迁移备份可在帮助 → 传承存档下载。备份存储失败时明确提示并停止迁移，原档和当前局保持原样。负余额、非数值、超安全整数与损坏应计分数会拒绝载入。本批测试使用构造的旧格式样本，没有读取或修改玩家日常浏览器中的真实存档。

新增独立的 difficulty（id、rulesVersion、selectedAt）、规则查询入口及按代的救援使用记录。现阶段标记为 legacy/旧版规则；收入和闭关费用读取中性规则配置。动作状态仍使用 G.mode。继承保留规则版本，下一代获得独立使用记录。

**大众/硬核的选择、锁定、旧档升级分支、实际救援与惩罚尚未开放**，分别留在 D1、D2 制作。没有投放不能生效的模式按钮。

## 实现与验证

应计权益用约分后的整数字符串分子/分母保存，计算时使用 BigInt，不循环累加浮点日薪。合同只按 last 至当前日期或到期日之间的实际天数结算，last 随结算保存；死亡和事件中断只结已发生的时间。

新增 tools/economy40.js、tools/help40.js，发布副本在 prototype/assets/；既有地方、人物、药路与铺账脚本也同步更新。入口仍为 prototype/index.html，存档键不变。

- node tools/economy40-check.cjs：29项通过，覆盖整段/逐日/跨年跨世纪、40枚看护合同、权益存读档、迁移幂等、原档下载、存储失败、异常余额、恰好够价、死亡与事件中断、实际后人、六主身份与手机帮助操作。
- 原有四套玩法回归：34＋34＋41＋12＝121项通过。world36 的一条旧文案断言改为检查“没有合格后人时不新增人物、无接续按钮并显示原因”，以匹配帮助整理后的简明说明。
- node tools/visual40-check.cjs：113项界面回归通过；基于原界面检查，输出独立保存在 batch40/ui-regression。
- 合计263项检查通过，无浏览器或资源错误；受控 Edge 独立上下文，不代表九境全流程平衡、大众/硬核验收或手机真机验收。
